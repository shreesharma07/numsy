REST API

Everything the dashboard does is available over HTTP on this machine. The API listens on 127.0.0.1 by default, accepts same-origin requests only, and uses the same engine and settings as the numsy CLI.

Your data stays on this computer. Uploads are parsed in memory and dropped after an hour of inactivity or when the server stops. Numsy does not store file contents, never sells or shares them with third parties, and never uses them for AI training. Privacy & data disclaimer

Typical flow

# 1. Parse a file into a session (CSV or .xlsx, up to 50 MB)
curl -F "file=@contacts.xlsx" http://localhost:6789/api/parse
# → { "sessionId": "…", "totalRows": 1200, "columns": [...], "detected": { "phoneColumn": "Mobile" } }

# 2. Page through results with any settings
curl -H "Content-Type: application/json" http://localhost:6789/api/view \
  -d '{"sessionId":"…","settings":{"dedupe":"first","only":"valid"},"query":{"page":1,"pageSize":50}}'

# 3. Export exactly what you see
curl -OJ -H "Content-Type: application/json" http://localhost:6789/api/export \
  -d '{"sessionId":"…","format":"xlsx","settings":{"dedupe":"first","numberHeader":"Mobile"}}'

Endpoints

GET/api/meta

Version, upload limit, accepted extensions, export formats and default settings.

POST/api/parse

Multipart upload with a file field (.csv or .xlsx). Parses in memory and opens a session. Returns sessionId, name, totalRows, columns, detected.phoneColumn / detected.nameColumn, size and parseMs.

POST/api/text

JSON { "text": "…", "mode": "extract" | "validate" }. Opens a session for pasted text: extract finds numbers anywhere, validate reads one value per line.

POST/api/view

JSON { sessionId, settings, query } with query = { page, pageSize (≤ 500), search, allColumns }. Returns summary, counts per row set, columns, the page of rows (each with a status of valid, invalid or duplicate), total, page and pages.

POST/api/export

JSON { sessionId, format, settings }, or { text, mode, format, settings } without a session. format is csv, xlsx, json, md or txt. Responds with the file as an attachment and an X-Numsy-Rows header.

POST/api/analyze

One-shot analysis: multipart file plus any settings as form fields. Returns the full report: analytics, phoneColumn, rows, validRows, invalidRows, duplicateRows, unique and durationMs.

DELETE/api/session/:id

Forget a session immediately.

GET/api/health

{ "status": "OK", "timestamp": "…" }

POST/api/upload Legacy

The 1.x upload: processes a file with default settings and returns a downloadId for GET /api/download/:id, a ZIP of valid and invalid CSVs, unique numbers and an analytics report. Temporary files live in a private folder and are deleted after download.

Validation rules

Digits are kept and a +91, 91 or leading 0 prefix is removed. A valid number then has exactly 10 digits and starts with 6, 7, 8 or 9. With strict on, dummy patterns such as 9999999999 and 1234567890 are rejected too.
